## Current Trash verification

TickTick's deleted-row context menu showed **Restore** and **Delete Forever**. Restore returned an assistant-owned disposable task to its original Inbox, removed it from Trash, left the Trash view open and displayed a transient `Restored to "Inbox"` toast with a right chevron. The chevron's destination was not established. Moving the probe back to Trash produced `Task deleted` with an orange Undo arrow. Permanent deletion was not executed.

Taskovsky live checks on a separate disposable task: Move to Trash produced the dark `Task deleted` toast with Undo; it was absent after a six-second wait. Undo returned the task to its list. Both the Trash detail button and row context menu restored the probe to Inbox with a `Restored to "Inbox"` toast; the toast chevron navigated to Inbox. The context menu's Delete Forever opened a confirmation explaining that deletion cannot be undone; Cancel preserved the task. The probe was subsequently moved back to recoverable Trash. Automated test counts reported in the implementation status need to be re-run or linked to an authoritative result before being treated as current evidence.
