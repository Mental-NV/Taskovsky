# MOB-CAPTURE-001 — Local task/note capture

Status: Verified for the documented Mac and simulator cases. Approved by the autonomous local desktop/mobile Tasks and Calendar request, November 9. The work remains isolated on `codex/mobile-local-prealpha` at dirty base `6ee96ee`; the original Desktop checkout and prior checkpoints are preserved. No commit/push, deployment, signing-account change, external integration or permission prompt.

## Intended outcome

Implement IOS-005/006/011/012, BUS-003/010 and the S5 capture portion. Normal phone launches must be able to create tasks/notes locally. Extract the actual Mac creation/default/recognition/template policies into Domain with a compatibility facade, retaining Mac behavior and URL-title dispatch there only. Both platforms must call the extracted policy. Phone presentation is a proposed native adaptation; there is no capture reference screenshot and no claim of reference visual approval.

Capture shows Task/Note, title, optional plain description, list/Inbox, date/time, priority, existing tags, removable date/tag recognition and template selection. Resolve and display defaults/context before submission: Today/Next 7 Days use today, Tomorrow uses tomorrow, list and tag routes supply their IDs, explicit Inbox overrides the configured default list, Calendar supplies its focused date. Show archived/default fallback as Inbox before editing. An explicit selected target removed/archived while drafting is refused at save, without silent redirection. Unknown tag tokens stay as text; the phone does not create tags implicitly. Recognition only resolves existing IDs; multiword names are available through the native picker. No workspace mutation occurs while editing or applying templates.

Applying a template changes only the draft after confirmation when replacing content. Preserve exact rich text, embedded checklist, recurrence and duration; styled description stays read-only. Editable title/kind/priority/list/tags and explicit date changes own only those values. Template creation retains the Mac path's distinction from quick entry (no automatic reminder defaults on untouched template schedules). Date choices explicitly re-anchor/clear duration, without inventing a new recurrence policy. Do not flatten malformed/unsupported template payloads; refuse instead.

## Transaction and recovery

A capture owns one stable UUID, used as the new record's ID/command identity, and a fixed creation instant plus base workspace/settings revision. A prepared command is durably saved in a separate versioned scratch record before attempting the workspace write. Retry checks for the same record ID and exact submitted payload before revision refusal; it never adds a second record. A conflicting same ID is refused. This is a single-process local command, not a distributed ledger or shared-file protocol; independent live-file mutation/purge is unsupported.

Known whole-document compatibility is required. Validate a nonempty final title, current target/list/tag identities, schedule/template safety, and a safe append without rewriting settings. One atomic workspace replacement publishes the task. Failed or uncertain writes retain the draft; re-read the ID to confirm actual success if a writer threw after replacement. A confirmed no-write may return to editing; uncertain completion stays frozen for Retry/query. Duplicate submission and IME-marked text are guarded. App backgrounding never submits.

Capture scratch contains only input/new-record intent, compact base revision, version, identity, sequence and timestamps, not another workspace. Reuse the field draft service's exact encoding, unknown-file preservation, sequencing, close/cleanup retry and late-callback guards. Resume/Discard never auto-submits. Do not allow a capture and field editor to replace each other's recovery. Acknowledged scratch success is distinct from task success; 250 ms/background writes retain the already documented pre-acknowledgment termination window.

## Presentation and acceptance

Add a 48-point floating Add button above the capsule on Tasks/Calendar/Search when writing is permitted. Use a large native sheet, title focus, explicit Cancel/Add, system fonts, existing blue accent, native grouped-form insets and scrollable metadata controls. Dirty cancellation asks Discard/Keep Editing and blocks interactive loss. Successful durable creation dismisses, displays feedback and opens the created detail even if it does not match the current query. A restored submitted command can only Retry/check or discard; controls must not imply a new record has already been saved.

Verify shared Mac characterization/defaults/recognition/template behavior, exact rich and all unowned data, explicit Inbox and stale/removed/archive target handling. Test successful/failed/after-write-throw/retried/duplicate/concurrent submissions and restart recovery with stable identity. Use neutral UUID-isolated simulator fixtures for native Cancel, context/pickers, Task/Note, template protection, failure, relaunch and single-create assertions; audit actual files and Mac reload. Run full Mac suites/release and affected iOS tests/build, review actual captures, update current specs/parity/verification and preserve a separate source checkpoint. Physical/IME/accessibility/performance gates remain explicit if not exercised.

## Implementation disposition

[Verification](../spec/verification.md#mobile-local-capture) records 530 Mac cases, 69 distinct simulator cases across the full run and corrected focused tests, and 23 fixture file audits plus the focused note recheck. The initial full-run note failure was a pre-tap visibility assertion; the successful save and its fields were separately audited. The corrected note check passes on identical app binaries. The Calendar capture check exposed a one-card all-day limit; hourly lanes now expose all entries, Month overflow opens Day, and Today uses the live session clock. The capture UI uses a native grouped form, with draft status and an explicit Keep Editing action after a confirmed write failure. Reference visual acceptance, physical/accessibility/device gates and broader S5 workflows remain open.
