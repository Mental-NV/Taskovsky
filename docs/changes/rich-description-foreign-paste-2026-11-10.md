# RICH-CLIPBOARD-003 — Supported formatting from other apps

[Verification](../spec/verification.md#foreign-rich-description-paste).

TickTick documents retaining supported inline formats from rich clipboard sources. Its examples include bold, italic and links. This change follows that documented behavior on Mac and iPhone. [TickTick formatting guide](https://help.ticktick.com/articles/7507338582718152704).

- Ordinary description paste gives a matching Taskovsky fragment first priority. For a single foreign HTML or RTF item, it imports supported inline marks into the same paired description edit. HTML supports semantic bold, italic, underline, strikethrough, inline code, mark and HTTP or HTTPS links. It reads inline CSS weight, style and text decoration. RTF imports bold, italic, underline, strikethrough and HTTP or HTTPS links recognized by the native RTF text decoder.
- When the item provides plain text, the saved description preserves its exact UTF-16 code units. Rich spans must align to the same text after allowing layout whitespace differences. Mismatched or unreadable rich data falls back to that literal representation. An HTML-only or RTF-only item can supply its own text. If both forms are present without plain text, a successfully decoded HTML representation supplies the text. Paste as Plain Text applies the same literal text without marks or Markdown inference.
- The reader uses a bounded in-memory HTML parse and maps supported values to Taskovsky’s existing model. The HTML path ignores scripts, styling resources, media and other embedded objects. Only explicit, supported web links become clickable. RTF objects, embedded images and external-content instructions are refused. The [HTML paragraph follow-up](rich-description-foreign-html-blocks-2026-11-10.md) adds supported semantic blocks. RTF paragraph formatting, media, fonts, arbitrary colors, tables and broader source fidelity remain outside the conversion.
- Pasting replaces the current selection as one editor edit. Mac uses its per-document Undo. iPhone uses draft Undo and Redo, followed by an explicit Done to save the text and styles together. The storage schema is unchanged. Plain-text Markdown recognition and Taskovsky-to-Taskovsky block paste have their existing paths.
- Verify exact text, safe link ranges, native ordinary and literal paste, Undo, Redo and saved-file reopen with synthetic items on named QA pasteboards. External services and clipboard synchronization are outside this work.
