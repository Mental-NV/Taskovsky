# Acknowledge saved custom-filter drafts

Status: implemented correction after an owned blocked-write regression failed for both create and edit. Before this correction, Mac Save mutated the visible workspace before writing and dismissed the filter editor regardless of persistence. A complex nested-filter draft can appear saved but be lost on reopening the app.

Scope is Mac filter create/update only. Validate the existing filter command against a staged workspace, refuse a stale original filter, then persist before publishing. The editor keeps a stable new-filter UUID across retries. Failure leaves all draft fields and nested rules visible, retains the sheet, and shows a multiline leading 12-point semantic-red error immediately above existing Cancel/Save buttons. No new icon/animation, rule semantics, existing layout dimensions or iPhone UI change. Cancel remains explicit abandonment; successful Save dismisses once.

Preserve unknown data rather than round-tripping the whole workspace. A pure lexical helper patches only the selected filter record or appends a new one to the filters array. Unrelated raw JSON, records and unchanged fields remain byte-preserved, including unknown fields and valid noncanonical legacy defaults. Update only changed known fields. A changed field whose old raw value cannot be losslessly understood is refused with an actionable compatibility error; do not strip unknown nested rule content. Duplicate JSON keys, duplicate filter IDs, stale/deleted original filters or disk/store disagreement are refusals, not success. Missing filters/defaults are accepted when their decoded meaning matches the existing model. A fully absent initial workspace may be created only for an empty current store.

No concurrent external writer/lock guarantee is introduced. Recheck the disk bytes immediately before atomic replacement, preserve all in-memory state on failure, and require a fresh editor after a conflicting saved filter change. An unrelated change already acknowledged by the same store is retained. General external-file reload, other entity operations and legacy autosave remain outside this fix.

Verification: fail-before/pass-after blocked create/edit and retry; stable ID/no duplication; preserve nested/dead selections/pin/order; unknown top-level/task/filter/unchanged-rule bytes; legacy missing/alias keys; refuse incompatible changed rule, duplicates, stale/deleted filter and changed disk without writes. Native owned-file failure/retry check is separate evidence, not inferred from unit tests.

Native attempt limitation: the UI tool could not expose the hover-only Add filter control, so no draft was staged and Save failure/retry was not exercised. The stable guarded QA app, fixture and defaults were restored exactly. Unit/source evidence does not establish rendered error wrapping or live draft retention.
