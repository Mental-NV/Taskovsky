# MOB-PERSIST-001 — Conservative local metadata repository

Status: Implemented for the bounded cases below; current evidence/limits are in [verification](../spec/verification.md#mobile-foundation-preview). Authorized under the autonomous local mobile parity request. Bounded S3 continuation; no real-data UI or deployment.

Add an explicitly injected, serialized local repository around the immutable read snapshot. Never default to Mac paths. Preserve original workspace/settings bytes for reading. Enable only title and genuinely plain-body patches when the entire workspace and settings survive a canonical structural JSON round trip through their known models. Any unknown key/version/payload elsewhere, implicit decode sanitation or lost field locks the whole document for writing; decode failure remains unavailable, never writable empty. This conservative gate may lock valid legacy files and is not an opaque-field preservation format or migration.

Commands use an opaque expected revision covering both original files. Re-read and compare before each commit; stale, missing, trashed or archived records are refused. Keep styled/malformed body companions read-only for body edits. Title patches retain all body/rich/schedule/hierarchy/lifecycle fields. A no-op changes no timestamps or bytes. Stage the new snapshot and atomically replace only the workspace before publishing durable success; failed persistence returns failure and leaves the loaded document authoritative. Settings are not rewritten. One repository actor serializes in-process commands; do not claim multi-process locking or sync. No capture/lifecycle command is introduced here.

Test known styled metadata/UTF-16 and all unowned fields, unknown payload on another record/settings, malformed/unreadable data, no-op bytes, stale revisions/competing commits, unsupported-body refusal, archive/trash/missing guards and injected write failure. Run on Mac and the simulator before wiring phone editing. No writable phone control is enabled by this repository-only slice, and its restrictive compatibility gate must remain visible when later UI is added.
