# Mobile Schedule Date/Duration presentation

Live TickTick observation established Date/Duration tabs: Date has a month grid, Duration has start/end summaries. Switching a date-only reference draft to Duration produced a timed hour, which was canceled. Reference saved conversion defaults and consistency across task kinds are unverified.

This bounded Taskovsky presentation change replaces the Duration switch with Date/Duration segmented choices. Date keeps the graphical date selector. Duration uses existing Start/End controls; the existing whole-range Date move is retained under a collapsed “Move duration to another date” disclosure rather than left as a third always-visible picker. Existing Time, shortcut, reminder, repeat, timezone, Remove and Cancel/Done routes remain.

The choices call the exact existing `TaskScheduleEdit.setDuration` method. A date-only draft stays all-day; a timed draft retains the existing configured default duration, and returning to Date keeps the existing end-date rule. No inferred TickTick conversion, persistence, schema or reminder rule is introduced. This is partial layout parity, not exact reference behavior or typography; full Duration cards and Time presentation remain incomplete. Selecting a type edits the draft, not a display-only mode; outer Cancel discards it.
