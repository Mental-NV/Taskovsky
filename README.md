# Taskovsky

A local macOS task and notes app inspired by TickTick’s three-pane task workspace. Built with SwiftUI and Foundation, with no third-party dependencies. Requires macOS 14 or later and Swift 6 / Xcode command-line tools to build.

## Build and run

```sh
./scripts/build-app.sh
open build/Taskovsky.app
```

You can move `build/Taskovsky.app` into Applications. The build is signed locally; it is not a notarized distribution build.

For development, `swift run --disable-sandbox Taskovsky`. Run the model tests with `swift test --disable-sandbox`.

## Features

- Tasks and notes with native rich-text descriptions: bold, italic, underline, strikethrough, headings 1–6, links, highlight, inline code, block quotes, horizontal rules, and bulleted/numbered/checklist paragraphs via a scrollable formatting toolbar with ⌘B/⌘I/⌘U and undo. List markers (bullets, continuing numbers, checked/unchecked boxes) and the quote gutter are painted by the layout manager from metadata in a reserved 24pt gutter — the persisted body stays prefix-free so styles, search, and the caret are never corrupted — with numbering that continues within a group and restarts after a break. Return in an empty list item, heading, or quote exits the block, including a second Return in the empty trailing paragraph (typing resets to plain while the preceding block keeps its style, and selection/toolbar reads follow the live typing instead of resurrecting it); heading/list/quote buttons also work in an empty document or the empty trailing paragraph, arming the first typed characters (list arms apply on next input because AppKit drops textLists from assigned typing attributes). Plain text stays authoritative for search, snippets, summaries, and previews; styles persist through duplication, templates, notes conversion, and reloads, and clear safely whenever the body is replaced. A heading key without heading font (or quote key without its indent) is stale and extracts — and strips — as plain, so the model, toolbar, and later reads agree. Undo is scoped to the owning document (switching tasks always invalidates, even for identical bodies) and the editor owns a per-view UndoManager, so clearing never touches the title field or other views. Notes live inside lists; date grouping has a Note section and there is no separate Notes tab.
- Editable, colored task/note lists and tags. Drag task rows to lists or Inbox to move them; drag lists to reorder them. The persisted None (manual) sort is one real sequence for all active tasks/notes regardless of dates or priorities, with in-row above/below insertion indicators; other sorts keep their groups and reject reorders with a message. Legacy Manual sorts read as None. Reordering starts from the row's hover-or-selected grip, never the whole row.
- Task pinning: Pin/Unpin from row or detail menus groups pinned active tasks in a Pinned section above normal groups under every sort, with the None drag policy unchanged (each side stays its own reorder group; crossing the pinned boundary explains itself with a message instead of silently absorbing the drop). Completed, Won't Do, and Trash never show pinned rows; the flag survives those states so reopening or restoring brings the pin back. List moves keep the pin.
- List archiving, duplication, and smart-list inclusion: Archive/Unarchive from the list menu (Archived Lists section, read-only content, reminders suppressed, hidden from smart destinations); Duplicate List copies non-deleted tasks with new IDs and styles; the Show in Smart List toggle hides a list's tasks from smart destinations while reminders keep firing. Explicitly selecting an archived or excluded list (filters, summary, search) still shows its content.
- Nested tags with persistent collapse, sub-tags, cycle-safe reparenting, merge (rewrites task/template/filter refs, reparents children), and full cleanup on delete. Parent tag rows include descendant-tagged tasks. Tags stay assignable in detail and quick-entry pickers.
- Saved filters with multi-priority, multi-date (this/next/last week and month, plus next month, repeating, inclusive custom ranges), task/note types, and Any/All/No-tags/Any-tag matching, plus an Advanced AND/OR/NOT rule builder with explicit empty-group semantics. Legacy single priority/date filters keep their meaning. Fresh rule conditions start with their displayed defaults (Today, no priority, task type, uncompleted); unconfigured list conditions match nothing. Deleted list/tag selections persist as no-match (renaming never broadens a filter) and surface as unavailable rows for deliberate clearing; rule trees are never rewritten and merging tags repoints rule conditions. Conversions preserve conditions (no inserted always-true placeholders) and NOT(list A) never grants an archive override. Duplicate task IDs in a malformed file render last-wins instead of trapping the list.
- Pinned shortcuts for lists, folders, tags, and saved filters in a Pinned sidebar section with the same navigation and counts; pinned folders expand inline.
- Isolated visual-QA launch: `python3 scripts/seed-qa-fixture.py` seeds `/tmp/TaskovskyQA` (rich showcase with horizontal rule, archived/excluded/pinned lists, nested/pinned tags, saved filters, a subtask pair, a custom repeat series, and a duration window), then `open build/Taskovsky.app --args --workspace /tmp/TaskovskyQA/workspace.json` runs the app against that fixture only (normal launch is unchanged; the real workspace is never touched). Flag presence alone isolates: a bare `--workspace` (or a missing/invalid value) falls back to a fresh per-process temp workspace with a warning, never to real data; only absolute file paths (never directories, never another flag) count as explicit values. Preferences run in an isolated suite while a workspace override is present. Dates are seconds since 2001-01-01 UTC (Swift's default Double strategy); the fixture covers rich styles with computed offsets and no literal list markers, an archived/excluded/pinned/board lists, nested/pinned tags, saved filters incl. an advanced NOT, a subtask pair, a custom weekly series, an end-count series, a scheduled window, a same-body undo pair, and an empty draft.
- Single-level folders group lists: create/rename from the Lists heading or context menus, collapse with the disclosure, Add List into a folder, move lists between folders or back to root by drag or menu, Ungroup keeps lists and tasks. Folder and list rows reorder by drag with insertion indicators.
- Configurable All, Today (including overdue), Tomorrow, Next 7 Days, Inbox, Summary, Completed, Won't Do, and Trash smart lists. Top and bottom smart groups each reorder by drag within their group (order persists, hidden entries keep their slots); right-click a smart list for Edit (opens Settings → Smart Lists), Show if not empty, or Hide. Hiding the active list navigates to a visible default.
- Due dates, optional times, daily/weekday/weekly/monthly/yearly repetition, an inclusive recurrence end date, previews of repeating days, multiple custom reminders, and multiple timed/all-day reminder defaults.
- Custom repeat rules (every N days/weeks/months/years, weekday picks, monthly each/on-the/workday patterns, yearly month/day, skip-weekends, specific dates, end by date or count) with a live occurrence preview, remaining-occurrence counts, and per-position series tracking; a valid custom rule supersedes the simple repeat choice. The staged schedule editor (Cancel/Clear/OK) labels custom series, previews upcoming occurrences, and resets the series position only when the rule changes — ordinary date edits never reset the count. Strict month-day parsing rejects bogus tokens instead of dropping them.
- Scheduled durations (timed or all-day windows) with editor pickers, a default length for newly created timed tasks, and a duration suffix on the schedule button. The standing policy is `dueDate == scheduledDuration.end` with `hasDueTime == !isAllDay`: creation, save/update, template instantiation, and recurring successors all end-anchor the window at the due date (timed keeps exact elapsed seconds, all-day keeps whole-day spans across DST); invalid windows drop and no record is ever undated while holding an absolute window (dateless templates may store a bare shape, but instantiating one brings its own due).
- Subtasks: completing a parent completes its active subtree in one instant (already-done/Won't Do preserved) with reload-safe undo that reopens only cascaded children; recurring parents clone the subtree once under the successor (dates/reminders/windows shift with the occurrence: elapsed for timed, calendar-day for all-day). Trash/restore cascade recoverably (separately trashed children stay), purging detaches survivors, duplication copies whole subtrees with remapped links, and moves carry descendants (a moved child detaches; cross-list parenting normalizes). Undo never leaves duplicates or dangling links: reopened children shed their pristine spawns, and edited spawns are retained with their required ancestors. Parent links reject note/trashed/archived records, subtask creation rejects archived/note parents, and archived lists freeze edits at the store layer while move-out stays allowed. Child/parent titles navigate (drawer and pop-up swap in place, drafts preserved); rows show per-parent progress with row-menu and detail reparenting (same-list active candidates, cycle-safe) and independent filtering.
- Per-list Kanban boards (List/Board toggle in the list header and the list editor; each list remembers its own mode across rename, edit, duplicate, and reload): every non-deleted status in the list splits into Open, Completed, and Won't Do columns with counts, independent of the rows' Show Completed toggle — a completed drop stays visible and an all-completed list still renders its columns instead of the empty state. Dropping a card changes its status (completion, undo, and reopen all work from the board; completing a recurring task spawns its successor like the checkbox; notes stay open and refuse status columns with a message). Archived lists render read-only; hierarchy renders flat. The board is status columns only — no custom sections or column editing.
- Local Calendar with Day, Week, Month, Year heatmap, Agenda, configurable Multi-Day and Multi-Week views. Create timed/all-day tasks, drag to schedule or move, resize timed blocks, use Schedule… for precise edits or removing dates, and Undo schedule without losing text edits. Arrange tasks by list/tag/priority; filter lists and descendant tags; choose task colors, filled/outline styles, completed/checklist/repeat visibility, and an additional local time-zone ruler. Future repeat cycles are read-only previews. Calendar uses the existing local tasks and settings; external calendars, subscriptions, import/export and sync are deliberately deferred in the [parity document](docs/ticktick-spec/taskovsky-parity.md#calendar-integrations-deliberately-deferred--8-november-2026).
- Four priority levels, sorting, completed history, duplication, conversion between tasks and notes, and recoverable task deletion.
- Search tasks, notes, lists, tags, and saved filters with highlighted matches, relevant snippets, keyboard navigation, and separate completion actions. Press Return in quick search for full results with date/list/tag/status criteria, then save those criteria as a filter.
- Local editable plain-text summaries with period/list/status filters, grouping, field selection, next-period tasks, Copy, and Save as Note.
- Settings (⌘,) for smart-list visibility, week start, week numbers, scheduling time zones, recognition, task defaults, templates, and About.
- Live date highlighting, date recognition preview with an ignore action, tag suggestions, and Shift-Return descriptions during quick entry. Double-click a row title to rename it inline. Date/time and #tag recognition during quick entry. Optional URL-only title parsing fetches the page title; disable it in Settings to keep URLs unchanged.
- Built-in and custom templates, a template gallery, and saving an existing task as a template.
- A five-second completion Undo message and a completion chime. Undoing completion safely handles the next recurring occurrence.
- Resizable task/detail panes, an animated collapsible list sidebar, collapsible Lists/Filters/Tags sections, saved panel sizes, and list symbols or emoji. Task-row metadata hides as whole items at narrow widths, with optional body preview and checklist rows from the More menu. Narrow windows switch the detail to a 300pt overlay drawer (Side peek) or a separate pop-up window (View Options); wide windows dock it. Very narrow windows auto-hide the sidebar (manual preference remembered, toggle reveals an in-window navigation overlay) down to the live-verified 382x580 minimum (382x552 content floor plus native chrome).
- In-app reminders with snooze and dismiss. No OS notifications or background service; check Reminders while the app is open.
- Every edit saves locally and atomically to `~/Library/Application Support/Taskovsky/workspace.json`; preferences save beside it in `settings.json`. An unreadable file is preserved, and save failures remain visible. Existing workspaces migrate without losing tasks. The app automatically migrates data and preferences from the previous misspelled app name on first launch.

Use **⌘N** to add a task, **⇧⌘N** to add a note, and **⇧⌘L** to create a list. Press Return in the quick-add field or a checklist field to add an item. Right-click task rows, lists, or tags for actions. Click an item to edit it in the detail pane. Date changes apply with OK; Escape or closing the popover leaves the schedule unchanged. Clear removes the schedule.

Deleting a list moves its items to Inbox. Deleting a tag removes it from items. Deleted tasks and notes remain in Trash and can be restored; an individual trashed item can also be permanently deleted via its context menu, footer, or detail banner after an explicit cannot-be-undone confirmation. There is no Empty Trash or bulk purge.

Eisenhower Matrix, Pomodoro, habits, countdowns, accounts, statistics, server sync, system notifications, help, and voice dictation are intentionally excluded. No TickTick data is imported. URL-title recognition is the only network feature; tasks and settings stay on this Mac.

## Layout reference

The installed TickTick app was inspected through Computer Use. Taskovsky follows its list/tag sidebar, date-grouped rows, quick-add bar, and separate detail pane with scheduling and priority controls. This is an independent implementation of the requested subset, not a pixel-perfect clone. Reference observations used here: smart-list context menu (Edit, Show if not empty, Hide; Edit opens a settings smart-lists pane), folder context actions (Add List, Edit, Pin, Ungroup — Pin observed but not requested and not implemented) with a name-only folder dialog that preserves lists/tasks on Ungroup, and indented folder children under a disclosure. No native TickTick drags were verified. Native drag/resize gestures remain unreliable under Computer Use and are not claimed as verified; the request text is authoritative for drag behavior.
